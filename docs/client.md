# mdcompiler C Client

`mdcompiler-client` is a small C program that starts the `mdcompiler`
executable, forwards its output, and returns its exit code. It adds
`--protocol` to each request so callers can consume `MDCOMPILER/1` events.

The client uses the native process API (`CreateProcess` on Windows and
`fork`/`exec` on POSIX). Arguments are passed as separate process arguments;
they are not composed into a shell command.

## Build

Build both the compiler and client with CMake:

```sh
cmake -S . -B build
cmake --build build --config Release
```

The client is installed alongside the compiler:

```sh
cmake --install build --config Release --prefix install
```

## Command line

```text
mdcompiler-client <mdcompiler-path> <build|compile|run> <source> [options] [-- program-args]
```

Examples:

```sh
mdcompiler-client ./build/mdcompiler build examples/hello.c
mdcompiler-client ./build/mdcompiler run examples/hello.cpp --compiler clang++
mdcompiler-client ./build/mdcompiler run examples/hello.cpp -- --verbose
```

On Windows, use the executable paths generated by the selected CMake
configuration, for example:

```powershell
.\build\Release\mdcompiler-client.exe .\build\Release\mdcompiler.exe run .\examples\hello.c
```

Compiler options are forwarded unchanged. Use `--` to separate compiler
options from arguments intended for the compiled program.

## C and C++ callers

The client is a standalone C executable, so C and C++ applications can invoke
it using their platform's process API. For example, from a shell:

```sh
mdcompiler-client /path/to/mdcompiler build source.c --std c11
```

Do not pass untrusted input through a shell command string. When invoking the
client from an application, prefer an argument-vector process API such as
`CreateProcess` with correct argument quoting on Windows, or `exec`/`posix_spawn`
on POSIX systems.

## Protocol and exit status

The client forwards standard output and standard error from `mdcompiler`.
Protocol events use the `MDCOMPILER/1` prefix, for example:

```text
MDCOMPILER/1 status=ok phase=compile language=c compiler="clang"
MDCOMPILER/1 status=ok phase=compiled output=executable exit_code=0
```

The client's exit code is the compiler's exit code. Invalid client arguments
return `2`; a compiler executable that cannot be started returns `127`.
